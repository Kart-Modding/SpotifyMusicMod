Settings screen concept

How each part maps to Minecraft

  • Screen layoutA Screen with a header and footer. Skip the background blur on the left so the world stays visible.
  • Scrolling listContainerObjectSelectionList, one entry per row. It brings wheel, scrollbar and clipping.
  • ON/OFF and optionsVanilla Button, as in the current screen. Right-click to go back needs a small subclass.
  • SlidersSubclass AbstractSliderButton.
  • Search and hex inputVanilla EditBox. Search rebuilds the list entries.
  • TooltipsTooltip.create on each widget.
  • PreviewCall the HUD renderer inside the screen with a pose translate, so preview and game can't drift apart.
  • Move on screenA second Screen like PaperDoll's VisualConfigEditorScreen: no background, guide lines, mouseDragged to move, mouseScrolled to resize. The HUD renderer must also report its box for hit testing. Position is still saved as corner plus offsets.
  • Round cornersGUI fills can't do this. Generate a white rounded shape at high resolution, upload it with Textures, and draw it as a tinted nine-slice. Covers need a matching rounded mask.
  • Colour slidersA small custom widget built from fills. This is the only new widget type.
